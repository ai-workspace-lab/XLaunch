# XLaunch 设计 brief

日期：2026-09-05。状态：用户已选择琥珀色方向；原型与原生适配尚未实现。

## 名称与定位

产品名 **XLaunch**，项目仓库 [ai-workspace-lab/XLaunch](https://github.com/ai-workspace-lab/XLaunch)。副标题：Classic desktop, AI commands / 经典桌面，AI 指令。

延续 XWorkspace 命名，将 Launch 的应用启动与任务发起含义结合。此次命名决定针对产品和 GitHub 仓库；已有 `xworkspace-console` 服务名、目录约定、环境变量、二进制和发布包名暂时保留，避免破坏现有安装。

## Brief playback

为日常桌面用户及开发者设计一个轻量启动器：输入应用名称直接查找应用，输入动作找到系统能力，输入自然语言发起 Agent 任务。保留 2013 DDE Classic Launcher 的模糊壁纸、左侧分类、顶部搜索、中央高密度图标网格，以及彩色、有立体感的应用图标。

共用桌面无关核心，由各平台适配层提供入口和系统能力。不依赖 DDE 全家桶、Deepin Store、玲珑或 Deepin AI。用户随后将底栏独立命名为 [XDock](https://github.com/ai-workspace-lab/XDock)，在单独仓库维护；XLaunch 可搭配 XDock 或宿主原生 Dock。面板与窗口管理由宿主提供。

XDock 负责固定应用、运行状态与窗口切换；XLaunch 负责分类、搜索、系统动作与 Agent 指令。双方分别安装、运行和发布，通过可选的版本化接口联动；不把 XDock 嵌入全屏启动器，也不要求启动器必须安装 XDock。

## 已选视觉目标

![XLaunch 琥珀色方向](../../../assets/designs/xlaunch/amber-classic-selected.png)

采用暖琥珀色摄影壁纸模糊、浅色文字与轻微阴影、低对比透明边界、矩形分类选中条。参考稿为 4:3；实际原型要验证常见宽屏、小屏和缩放，而非拉伸整张图片。

原型起始规范：搜索框高约 40–48 个逻辑像素；分类栏约 180–210；文字 14–16；图标约 48–64；网格根据空间采用 6–8 列，保持标签可读。数值是实现起点，不是对生成图片的精确测量。无障碍模式提供不透明背景、更大文字、减少动画及清晰的键盘焦点。

## 交互约定

| 输入或状态 | 预期行为 |
| --- | --- |
| 空输入 | 分类 + 应用网格；开始打字进入搜索 |
| Firefox | 显示匹配应用，Enter 打开所选项 |
| 调低音量 | 显示明确的系统动作及目标，不依赖语言模型完成应用索引 |
| 整理下载文件夹 | 展示 Agent 意图与任务预览；执行前明确作用范围 |
| 多种解释 | 结果标明应用、系统动作或 Agent，用户选择，避免静默执行猜测 |
| Agent 不可用 | 说明状态，应用搜索与可用系统动作继续工作 |
| 任务运行中 | 显示步骤、进度、取消及结果；关闭启动器与取消任务分开 |

搜索框默认文案：`搜索应用、系统操作，或描述任务…`。自然语言任务可直接输入，`/ai` 可作为可选的显式入口。AI 结果按需在搜索下方或浅任务区展开，不常驻聊天侧栏。

键盘：方向键选择、Enter 打开或执行已选动作、Esc 先退出搜索/任务预览再关闭启动器；Tab 遍历交互控件。全局唤起快捷键可配置，需验证各平台冲突。

## 桌面无关核心与适配层

这是架构提案，不代表已经验证平台 API 或确定 UI 技术栈。Qt/QML 可以进入技术验证；当前仓库 React 控制台继续承担现有控制面功能。

核心负责应用索引的统一模型、分类与搜索排序、意图结果、Agent 任务状态、权限边界及用户偏好。系统动作按能力注册；Agent 在用户权限范围运行，权限和执行记录可查看。

| 目标平台 | 适配职责与待验证入口 |
| --- | --- |
| macOS 26+ | 应用发现与打开、快捷键/菜单栏入口、系统动作、窗口与背景效果 |
| GNOME 50 | 薄扩展或桌面入口唤起核心；焦点、快捷键、全屏层与背景效果验证 |
| KDE Plasma 6.6 | 面板小部件入口；应用发现、系统动作、焦点与背景效果验证 |
| DDE 7.0 | Dock/桌面入口；独立核心，不调用完整 DDE 应用生态 |
| Xfce | 面板或桌面入口；合成效果可用性与降级背景验证 |

全部平台状态均为“计划 / 待验证”。Linux 可从标准桌面应用条目适配，macOS 使用本机应用发现机制。跨平台不假定共用同一 IPC、窗口置顶协议或模糊 API；无法实时模糊时采用本地壁纸模糊副本或纯色背景。

## 与仓库已有设计的关系

[2026-06-07 桌面方案](2026-06-07-ai-workspace-desktop-design.md)面向 Xfce 和浏览器控制平面，并将传统启动菜单排除出主要流程。本次新增跨桌面 XLaunch 产品方向：对于启动器体验，以本文为准；现有控制台、安装器及桌面配置继续保留，默认启动流程的迁移需在实现阶段单独设计。

## 下一阶段验收

制作琥珀色可交互原型：分类筛选、应用搜索、系统动作结果、自然语言任务预览、键盘导航和无结果/不可用状态。原型明确标注模拟执行。然后逐平台验证真实应用打开、权限、焦点、快捷键、背景降级及任务生命周期，逐项建立兼容性矩阵。
